給會 C#、但不是電機也不是資工的人

SCADA 入門圖解

先記住一句話：PLC 就是一排有編號的置物櫃。現場的訊號是電線上看不到的電，PLC 的模組把電翻譯成數字放進櫃子，你的 C# 程式照櫃號去拿數字。前期完全不用碰電線。

整頁都用這台機器當例子

一台洗脫烘洗衣機怎麼運作

按下開始後，洗衣機照順序跑：洗 → 脫 → 烘，洗完和脫水中間會多一次漂清。每一步就是把幾個設備打開或關掉，條件到了就換下一步。

步驟進水閥
00001		排水泵
00002		加熱器
00004		滾筒轉速
40001		燈／聲音什麼時候換下一步
1 準備關關關0綠門關好（10003＝1）→ 鎖門 → 門已鎖（10004＝1）
2 進水開關關0綠水位（30001）到 25 cm
3 洗衣關關關60 rpm綠時間到（約 15 分鐘）
4 排水關開關0綠水位回到 0 cm
5 漂清開→關關→開關60 rpm綠進水、轉、排水再做一次
6 脫水關開關1200 rpm綠時間到（約 6 分鐘）
7 烘乾關關開50 rpm綠時間到（約 60 分鐘），溫度維持 75 °C
8 完成關關關0黃＋逼逼 3 聲門鎖解開，可以拿衣服

這張表就是 PLC 程式要做的事（第 4 階段會練）。C# 不負責控制流程，只負責看「現在第幾步、數值多少、有沒有警報」。下一張圖的數值，就是第 7 步烘乾中的那一刻（上表反白那一列）。

第一張圖：訊號走到哪裡

從現場到你的程式

這台洗衣機總共 17 個訊號：5 個 DI、8 個 DO、3 個 AI、1 個 AO。

PLC 上插著幾塊模組，每塊模組上有幾個接點（就是接電線的螺絲孔）。一個設備的電線接到一個接點，每個接點固定對應一格櫃子，櫃子的編號就是位址。

照著第一排讀一次

開始鍵的電線，接到 DI 模組的第 1 個接點 → PLC 把它的狀態放在 10001 這格 → 沒按是 0，按下去變 1。

C# 想知道開始鍵有沒有被按，就去讀 10001。PLC 要開始進水，就把 00001 變成 1，DO 模組那個接點就會送電，進水閥打開。

燈和蜂鳴器也是 DO：紅燈就是 00007，寫 1 就亮；蜂鳴器是 00008，寫 1 就逼逼叫。

每一排都一樣：一個設備 → 一個接點 → 一格櫃子。17 個設備就有 17 格。這張「設備、接點、櫃號」的對照，就是工廠裡說的點位表。

最下面那一格：心跳計數器 40002

它不接任何電線，是 PLC 自己用的一格櫃子。PLC 程式每秒把它加 1：1527、1528、1529…。C# 每秒去讀它，只要數字有在跳，就知道 PLC 活著、網路也是通的。

PLC 這邊（每秒做一次） 
(* 每 1 秒加 1，加到 30000 就從 0 重來 *)
IF OneSecond THEN
  Heartbeat := (Heartbeat + 1) MOD 30000;
END_IF;
C# 這邊（每秒讀一次） 
// 40002 → 程式從 0 數，填 1
ushort hb = plc.ReadHoldingRegisters(1, 1, 1)[0];
if (hb == lastHb) stuckSeconds++;
else { stuckSeconds = 0; lastHb = hb; }
if (stuckSeconds >= 3) ShowOffline(); // 畫面變灰

為什麼不能只看「讀不讀得到」？因為有時候網路通、PLC 程式卻停了（例如切到 STOP 模式），數字還讀得到，但永遠不會變。心跳不動，才真的代表出事。

C# 永遠不會碰到電線。它只做一件事：透過網路，報櫃號，拿數字。電的部分 PLC 已經處理好了。

出狀況時

燈號與警報

每一條規則都是「看哪一格 → 亮哪盞燈 → 機器做什麼」。判斷的是 PLC 程式，SCADA 畫面同步顯示同一個狀態，並把警報發生的時間記下來。

條件（從哪一格看出來）燈號聲音機器動作
烘衣溫度 30003 超過 90 °C紅燈 00007一直逼逼關掉烘乾加熱器 00004
過熱保護開關 10005 跳開（變 1）紅燈一直逼逼開關本身直接斷電，不靠程式
水位 30001 超過 45 cm紅燈一直逼逼關掉進水閥 00001
門沒鎖（10004＝0）卻按開始不亮綠燈短逼 1 聲不准開進水閥（安全連鎖）
第 8 步：全部做完黃燈 00006，綠燈熄逼逼 3 聲解開門鎖 00003

第一層：程式判斷（軟體警報）

PLC 讀 30003，超過 90 °C 就關加熱器、亮紅燈。可以隨時改設定值，C# 畫面也看得到。

第二層：溫度開關（硬體保護）

熱到一定溫度，開關自己跳開把電切斷。就算程式當掉也有效。PLC 只是從 10005 知道「它跳了」。

紅燈警報的逼逼聲會一直叫，直到有人按停止鍵（10002）確認，這個動作叫「警報確認」。

第二張圖：看不到的訊號

電線上是「電」，櫃子裡是「數字」

現場的訊號是靠硬體接線帶進 PLC 的：感測器和 PLC 之間拉一條電線，線上跑的是電壓或電流。你看不到它，只能用三用電表量。PLC 上插著一塊塊「輸入模組」，負責把電翻譯成數字。

數位＝電燈開關只有開和關兩種狀態。線上不是 24V 就是 0V，模組翻成 1 或 0。（線斷了怎麼辦？看下一節）
類比＝水龍頭可以開一點點，也可以開很大。電流在 4～20 mA 之間連續變化，模組翻成 0～27648 之間的數字。
訊號電線上是什麼（看不到）誰負責翻譯櫃子裡變成
DI24V 有電／0V 沒電DI 輸入模組1 或 0
AI4～20 mA 電流，或 0～10 V 電壓AI 類比模組一個整數（西門子常見 0～27648，三菱常見 0～4000）
DOPLC 送出 24V，打開進水閥、點亮燈、讓蜂鳴器叫DO 輸出模組你寫 1 → 線上出現 24V
AOPLC 送出 4～20 mA，告訴滾筒馬達轉多快AO 類比模組你寫數字 → 線上出現對應電流

接線和模組設定是電控工程師的工作。你只要知道：同一個訊號在電線上叫「12 mA」，進了 PLC 叫「13824」，到了 C# 換算後才叫「100 cm」。三個講的是同一件事。

延伸問題

沒接到線，跟「關」有什麼不一樣？

用一般接法時，開關「沒按」和電線「斷掉」，線上都是 0V，PLC 都讀到 0，分不出來。如果斷的剛好是停止鍵的線，按了停止機器也不會停，這很危險。所以廠商會用下面幾種方法。

一般接法（常開）

狀況線上讀到
按下24V1
放開0V0
線斷了0V0
✗ 放開和線斷了一模一樣

用在不重要的訊號，例如開始鍵：線斷了頂多按了沒反應。

常閉接法（最常見）

狀況線上讀到
正常24V1
按下停止0V0
線斷了0V0
✓ 線斷了 ＝ 當作按了停止，機器停下來

還是分不出來，但錯也是往安全的方向錯。用在停止鍵、緊急停止、過熱保護開關。

加一顆電阻（斷線偵測）

狀況線上電流讀到
按下很多1
放開一點點（走電阻）0
線斷了完全沒有斷線警報
✓ 三種狀況都分得出來

要搭配有「斷線偵測」功能的 DI 模組。有一種叫 NAMUR 的感測器規格，也是同樣的原理。

延伸口訣 重要的接常閉，
斷線就當停機。

不改接線也能抓的方法

程式交叉檢查

用常理判斷：「門已鎖 10004＝1，但門關好 10003＝0」不可能發生，一定是開關或線壞了。進水閥開了 2 分鐘，水位 30001 都沒上升，也算異常。

雙通道（安全用）

緊急停止按鈕裡有兩組接點，一組常開、一組常閉，兩個訊號永遠相反。哪天兩個變成一樣，就知道線路出問題。安全繼電器就是這樣檢查的。

SCADA 端：通訊斷線

如果是 PLC 或整個模組斷線，SCADA 不會顯示 0，而是把數值變灰色、標「通訊中斷」或「品質不良」。另外放一個每秒加 1 的心跳計數器，數字不跳了就知道斷線。

本頁前面的洗衣機例子為了好懂，先用一般接法。實務上，停止鍵 10002 和過熱保護開關 10005 多半用常閉接法，正常時讀到的是 1，變成 0 才代表按了停止或過熱。

「出去」＝「設定」嗎？

是的。DO 和 AO 都是 PLC 送出去的命令，也就是「設定」：DO 設定開或關，AO 設定要多少。但設定了，不代表馬上就到了。

冷氣遙控器設 26 度這是「設定值」，是你送出去的命令 → 像 AO
房間現在 28 度這是「實際值」，是量回來的 → 像 AI

洗衣機也一樣：40001 是「請轉 50 rpm」的設定。馬達真的轉多快，很多機器會再多接一個 AI（例如轉速感測器）量回來看。SCADA 畫面常把兩個並排顯示：設定 50、實際 48。

// 寫設定值：40001 → 填 0；50 rpm 換成模組數字 = 50 / 1200 × 27648 = 1152
plc.WriteSingleRegister(1, 0, 1152);
// 讀回設定值確認有寫進去
ushort sp = plc.ReadHoldingRegisters(1, 0, 1)[0];   // 1152
背起來就好

五句口訣

口訣零　最重要的一句 線上是電，櫃裡是數；
中間靠模組翻譯。

電線上的電看不到，PLC 模組把它翻成數字，C# 只碰數字。

口訣一　四種訊號 D 是開關，A 是多少；
I 是耳朵，O 是手。

耳朵負責聽現場（輸入），手負責動現場（輸出）。

口訣二　四種櫃號 零一開關，三四數字；
一三只能看，零四能改。

Modbus 位址開頭的數字就是櫃號：0、1 放開關，3、4 放數字。1、3 是現場量到的，只能讀；0、4 可以由程式寫入。

口訣三　位址差一格 說明書從 1 數，
程式從 0 數。

文件寫 40001，C# 要填 0。讀到「隔壁格」的數字，九成是這個原因。

口訣四　4-20mA（唯一要懂的電） 4 是零，20 是滿，
掉到 0 就是斷線。

類比訊號用電流大小代表數值。故意從 4 開始，是為了讓「0」代表線斷了，不會誤以為是 0°C。

看懂 C# 那一行

括號裡的數字是什麼？

每一行 C# 都可以拆成四塊：方法名稱決定是哪一種櫃子，括號裡依序是哪一台、哪一格、寫多少（或讀幾格）。

plc.WriteSingleCoil(1, 0, true);
WriteSingleCoil哪一種櫃子、要做什麼
Coil＝0 號櫃（開關出去），Write＝寫入
1　站號哪一台 PLC
同一個網路可能有好幾台，像大樓裡的門牌。這台洗衣機設成 1
0　位址哪一格（從 0 數）
00001 是第 1 格 → 填 0
true　值寫多少
開關：true 開、false 關
數字：0～65535 的整數

整句翻成白話：「請 1 號 PLC，把 0 號櫃的第 1 格（進水閥 00001）設成開。」

讀的時候，第三個數字是「讀幾格」

ushort[] v = plc.ReadInputRegisters(1, 0, 3);
// 1 號 PLC，從第 0 格開始，連續讀 3 格
// = 30001～30003 一次讀回來
ushort level = v[0];   // 30001 水位
ushort water = v[1];   // 30002 水溫
ushort dry   = v[2];   // 30003 烘衣溫度

讀回來的是一個陣列，所以只讀一格時，後面要加 [0] 取出第一個。

動手玩一下

一個水位訊號的旅程

洗衣機的水位計量 0～50 cm，送出 4～20 mA。PLC 把電流轉成 0～27648 的數字放進 3 號櫃。C# 讀到數字後，再換回公分。拉拉看：

① 電線上（看不到的電）12.0 mA硬體接線帶進來，只能用三用電表量
② AI 模組翻譯後，放進 3000113824C# 讀到的原始數字
③ C# 換算後25.0 cm正常

水位 = 原始數字 ÷ 27648 × 50

公式怎麼來？想成兩把尺

兩把尺一樣長，只是刻度不同。換算就是：先看在第一把尺佔幾成，再找第二把尺上同一個位置。

水位
025 cm50 cm
模組數字
01382427648
例子① 佔幾成② 換到另一把尺
水位 25 cm（最高 50）25 ÷ 50 = 0.50.5 × 27648 = 13824
轉速 50 rpm（最高 1200）50 ÷ 1200 ≈ 0.0420.042 × 27648 ≈ 1152
讀到 1152，換回轉速1152 ÷ 27648 ≈ 0.0420.042 × 1200 = 50 rpm

1200 是滾筒最高轉速，50 是水位最高公分，這些看設備規格。27648 是西門子類比模組的「滿格」數字；它故意不用到最大的 32767，把上面那段留給「超出範圍或斷線」。其他品牌滿格不同，例如三菱常見 0～4000。

寫成 C#：一行程式，一句白話

兩把尺的兩個步驟，照順序寫成程式就是這樣。左邊是程式，右邊是它在做什麼。

例子 A：設定滾筒轉 50 rpm（寫出去）
const double MaxRpm = 1200;第一把尺的最高刻度：滾筒最快 1200 rpm。
const＝固定不變的數字；double＝可以有小數的數字
const double FullScale = 27648;第二把尺的最高刻度：模組滿格是 27648。
double rpm = 50;我想要的轉速：50 rpm。
double ratio = rpm / MaxRpm;① 佔幾成：50 ÷ 1200 ≈ 0.042（約 4%）。
double value = ratio * FullScale;② 換到第二把尺：0.042 × 27648 ≈ 1152。
ushort raw = (ushort)Math.Round(value);四捨五入成整數 1152。
PLC 一格只能放 0～65535 的整數，這種數字在 C# 叫 ushort；(ushort) 是「把它轉成這種格式」
plc.WriteSingleRegister(1, 0, raw);寫進 1 號 PLC、4 號櫃的第 1 格（40001）。
括號：哪台、哪格、多少
例子 B：讀水位，換成公分（讀進來）
ushort raw = plc.ReadInputRegisters(1, 0, 1)[0];從 1 號 PLC、3 號櫃第 1 格（30001），讀 1 格回來，拿第一個 → 13824。
讀回來是一排數字（陣列），[0] 是拿第一個
double ratio = raw / 27648.0;① 佔幾成：13824 ÷ 27648 = 0.5（一半）。
要寫 27648.0，不然整數相除會把小數丟掉，變成 0
double cm = ratio * 50;② 換到水位尺：0.5 × 50 = 25 公分。
Console.WriteLine($"水位 {cm} cm");在畫面印出「水位 25 cm」。
常見疑問

誰決定放哪一格？誰負責翻譯？

從 C# 這邊看過去，很容易以為什麼都要自己做。其實一個訊號從電線走到畫面，中間有三段，各有負責的人。

段落例子誰做要寫程式嗎資料從哪來
① 電 → 數字12 mA → 13824模組裡的晶片，自動翻不用，也沒有 library電控工程師在 PLC 設定裡選「這個接點是 4～20 mA」；0～27648 寫在模組手冊
② 數字 → 哪一格13824 放進 30001電控工程師或設備廠商，在 PLC 設定軟體裡安排不用寫，是設定通常有預設規則（第幾槽、第幾個接點對應第幾格），設好就固定；整理成點位表給你
③ 數字 → 公分13824 → 25 cm寫程式的人（在 PLC 或 C# 都可以）要，就是兩把尺的公式最高 50 cm 查感測器規格書或點位表

放哪一格，是我指定的嗎？

如果你只寫 C#：不是。就像訪客照門牌找人，門牌是建商（電控工程師）配好的，你拿點位表照著讀就好。

如果你也負責寫 PLC：才輪到你在 PLC 的設定軟體裡安排。設定好以後就固定，不會自己跑掉。

13824 是誰翻的？

模組硬體自動翻的，不用寫任何程式。你只需要從模組手冊知道「滿格是 27648」。

真正要動手的是下一步：把 13824 換成 25 公分。這一步沒人幫你做，要自己寫公式，最高值要查感測器規格書。

分工口訣 模組翻數字，電控排格子，
程式換單位。

所以接一台新機器，寫 C# 之前要先拿到兩份文件：點位表（哪一格是什麼、單位和範圍）和感測器規格（最高、最低是多少）。缺了它們，程式寫得再好也會讀錯。

點位表寫錯、一直找不到那一格怎麼辦？設定畫面長什麼樣子？C# 工程師第一次接 PLC 要照什麼順序做？請看續篇 C# 接 PLC 實戰。

讀不到、讀錯時

檢查口訣：先通、再讀、後對

① 通了嗎？

電腦連得到 PLC 嗎

  • 終端機打 nc -vz PLC的IP 502
  • 顯示 succeeded 就是通了
  • 不通：檢查 IP、網路線、PLC 有沒有開
② 別人讀得到嗎？

用 Modbux 讀同一格

  • Modbux 讀得到、C# 讀不到 → 改你的程式
  • 兩個都讀不到 → 問題在 PLC 那邊
③ 數字對嗎？

讀得到但數字怪

  • 是隔壁格的值 → 口訣三，位址減 1
  • 數字超大很奇怪 → 一個小數佔兩格，順序反了
  • 差固定倍數 → 換算公式不對
